# 显存与计算资源

## 先确定设备和任务

仅在任务用 GPU 时执行本节。确认框架版本、设备后端、分配的设备及其他任务占用。CUDA、ROCm、MPS 的工具和行为不同；没有 NVIDIA GPU 时不套用 `nvidia-smi` 或 CUDA 参数。在调度环境中保留调度器分配，不擅自覆盖设备掩码；若设置可见设备，记录物理设备与进程内序号的映射。

目标是在可用预算下得到稳定吞吐和正确结果，不追求占满显存。为最大输入、验证、保存和共享环境波动留实测余量。

## 诊断顺序

1. 区分模型加载即失败、首批峰值过大、输入形状变化、连续迭代持续增长、其他任务竞争。先看错误与小样本趋势。
2. 框架 allocated/reserved 与系统报告的进程占用不是同一指标。检查是否保留计算图、输出列表、重复模型或数据张量。不要仅凭 reserved 较大断言泄漏。
3. 优先去除当前代码不需要的长期引用、重复驻留和多余设备拷贝。推理若不需要梯度，可采用合适的无梯度上下文；需要梯度的推理/优化不能这样处理。`eval()` 与关闭 autograd 是不同操作。
4. 仍不足时，在任务允许范围内比较 batch、分块推理、混合精度、checkpointing 或 offload。它们可能改变数值、吞吐和训练行为，不是必开开关；训练中降低 batch 再累积也不保证与原方案严格等价。
5. 只有证据指向分配器碎片或特定形状问题时，查匹配版本的分配器选项。不要把某个环境变量作为所有任务的固定默认。

`empty_cache()` 只能归还未被活跃张量使用的部分缓存，不能释放仍被引用的张量或修复泄漏；不要每次迭代调用。当前任务结束后以所属进程和设备占用复核资源释放，而非要求共享 GPU 的总占用变成零。

## 小样本验证

预热后测量稳定段，同时覆盖较大输入或已知峰值阶段。GPU 异步执行下需正确界定计时边界；只在测量边界做必要同步，不给生产循环逐步加同步。注明同步方式与统计范围。

比较吞吐、峰值显存和输出正确性。任何精度模式变化需按任务的误差或质量标准验证；无标准时报告限制，不声称等价。显存降低但时间显著增加时，明确这是空间/时间取舍。
