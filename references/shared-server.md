# 共享服务器资源与任务管理

仅在共享服务器上准备或执行任务时应用。已有资源分配和使用约定清楚时直接执行，不增加逐项确认流程；只核实影响本次任务的未知边界。

## 资源归属与总预算

- 优先使用调度器或管理员分配的 CPU、内存、GPU 和存储；没有调度器时遵循服务器约定。当前空闲不代表独占授权，不覆盖已有设备分配或抢占别人的设备。分配不明时先查已有说明，只就必要的资源边界询问，不自行启动重负载任务。
- 预算覆盖主进程、所有 workers、分布式 ranks、BLAS/OpenMP 线程和同时运行的本任务实例；同时考虑 RAM、共享内存及 I/O 并发，不能只看 GPU 显存。具体估算沿用 I/O 和 GPU 参考，不固定按整机核数或空闲显存开满。
- 资源不足时减少本任务允许调整的并发、按既有调度机制排队或报告。排队中的任务不重复提交；不靠占显存空转来保留设备，不无限重试抢资源。

## GPU 新占用与连续实验

出现新进程或显存占用只代表资源状态变化，不作为自动停止、取消实验序列或放弃当前用卡安排的条件。先核验是否为本任务的 worker、其他已知任务或外来占用，再结合既有分配、服务器约定及下一条实验的实测资源需求判断。

- 当前任务已有有效分配或约定的连续使用时段时，切换实验不等于释放这项安排；资源足够且分配仍有效则继续，不默认后来进程优先。调度器明确到期、撤销或抢占时遵循调度规则，不能仅凭“先用”延长权限。
- 允许共享且资源足够时继续运行，不要求卡上只能有自己的进程，也不以整卡显存占用必须归零作为下一条实验的启动条件。
- 剩余资源确实无法满足下一条实验时，只暂缓该实验启动，保留队列、结果和恢复上下文，报告具体缺口；不因此终止仍正常运行的当前实验或取消整个序列。需要改变配置时遵循原有优化边界。
- 分配冲突或进程归属不明时记录证据并核实，不自动认定当前任务应退让，不终止对方进程。正在运行的任务只有在明确的调度要求、用户取消或已确认的运行故障需要处置时才进入停止流程。

## 任务可识别

tmux 会话、日志和输出目录遵循服务器命名约定，包含足以区分使用者、项目和任务的标识，避免同名覆盖。按生命周期参考保存启动时间、作业或会话 ID、进程身份和资源分配。共享账号下不能仅凭用户名判定进程归属；只读取排查所需的进程信息，不收集其他任务的环境变量或日志。运行记录保留在任务目录，公开提交前去除内部主机、路径和凭据等信息。

## 环境与系统变更

优先复用已验证环境。共享环境新增包也要检查对其他使用者和运行任务的影响；存在冲突时按环境参考选择任务专属隔离方案。只调整当前任务的配置，不修改全局 shell、系统限制、驱动、共享服务或他人的依赖。文件可写或账号具有管理员权限，不代表这些修改属于本次任务范围。

## 存储与传输

遵守目录配额及服务器的工作盘、临时盘约定。大规模读取、下载、解压和 checkpoint 写入控制并发与频率，避免短时间集中冲击共享存储；有现成缓存时核实有效性后复用，不为单次运行重复下载或复制整个数据集。缓存、日志和临时数据设置任务范围内的容量边界。

仅清理确认属于当前任务、已不再使用且不需保留的临时文件；共享缓存不能仅因由本任务创建就删除。保持正式输出与失败日志，清理历史产物或改变输出保留策略须在用户授权范围内。

## 退出与异常

按生命周期参考处理正常、异常和取消路径，回收本任务的 workers、释放设备并保存真实状态。出现新增占用时按上述 GPU 规则判断，不直接触发停止；已确认资源不足时仅在任务允许范围内调整自身负载或暂缓后续启动。不终止其他任务，也不重启共享服务或机器。归属不明的残留只报告，不凭进程名处理。长任务结束前不得宣称资源已释放；没有持续观察能力时提供后续检查入口。
